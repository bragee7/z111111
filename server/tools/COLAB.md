# Colab fine-tuning guide — ZELDA "Help me" keyword spotter
#
# Goal: take the measured 100 % recall / 5 false-alarms-per-49-clip baseline and
# push it to ~98 % recall / <0.3 FA per hour, by fine-tuning the published
# icefall Zipformer KWS checkpoint on a "Help me" dataset.
#
# Time: ~30 min on a free Colab T4 GPU (training) + ~10 min for eval.
# Cost: $0 (Colab free tier).

## 1. Open Colab
Go to https://colab.research.google.com -> New notebook -> Runtime -> Change runtime type -> T4 GPU.

## 2. Install icefall + deps (run once)
```python
!git clone --depth 1 https://github.com/k2-fsa/icefall.git /content/icefall
%cd /content/icefall
!pip install -q lhotse soundfile torch torchaudio onnx onnxruntime
!pip install -q sherpa-onnx
```

## 3. Upload the dataset
Upload the `kws_dataset/` folder you prepared (positives + negatives + eval) to
`/content/kws_dataset/`.  Or use the TTS bootstrap set generated by
`prepare_kws_dataset.py` (see step 4).

## 4. Prepare the dataset (run on your laptop first)
```bash
cd zelda1/server/tools
python prepare_kws_dataset.py --out ./kws_dataset --positives-dir ./kws_dataset/positives --negatives-dir ./kws_dataset/negatives
```
This downloads Fluent Speech Commands (free, public, ~100 h of non-command
speech) as negatives, copies your recorded "Help me" clips as positives, and
writes the icefall-format `data/fbank` features.  It also creates a held-out
eval split so the result is measured on unseen audio.

## 5. Train (on Colab)
```python
%cd /content/icefall/egs/gigaspeech/KWS
# stage 0: train from the published checkpoint (NOT from scratch)
!bash run.sh --stage 3 --stop-stage 3 \
  --exp-dir /content/kws_exp \
  --pretrained-checkpoint /content/icefall-kws-zipformer-gigaspeech-20240219.tar.gz \
  --data-dir /content/kws_dataset/data \
  --num-epochs 5 \
  --subset custom
```
The published checkpoint is at
https://github.com/pkufool/keyword-spotting-models/releases/download/v0.11/icefall-kws-zipformer-gigaspeech-20240219.tar.gz
(37 MB).  5 epochs on a T4 takes ~20 min.

## 6. Export to ONNX
```python
!bash run.sh --stage 2 --stop-stage 2 --exp-dir /content/kws_exp
```

## 7. Evaluate (run on Colab, or copy the ONNX back to the laptop)
```bash
python eval_kws.py --model /content/kws_exp/exported.onnx --eval-dir /content/kws_dataset/eval
```
Reports recall + FA/hour on the held-out set.  Gate the release on
recall >= 95% and FA <= 0.3/hr.

## 8. Ship it
If the gate passes, copy the exported ONNX files into
`zelda1/mobile/assets/kws/` and rebuild the APK.  The `KeywordModelManager`
already prefers the bundled files, so the listener will use the new model
with no code change.

## What "top of the class" actually costs
- Siri / Google Gemini use cloud models trained on billions of hours with 100x
  more compute.  They are NOT on-device free.  Your own constraints (FREE,
  LOW-RESOURCE, OFFLINE) rule them out by definition.
- The fine-tuned sherpa model (97.9% published) is the best measured option
  for a custom English trigger word on a phone.
- Physics caps "any decibel" at ~30 dB SPL (mic noise floor).
- "Zero cooldown" is unsafe: a single false positive in a noisy street fires
  SOS every frame.  Even Apple/Google keep a cooldown.
